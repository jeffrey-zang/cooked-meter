# Earshot

A song guessing game. You hear 0.1 seconds of a song, then 0.5s, 1s, 2s and so on. The less audio you needed, the more points you get (points halve every few seconds of audio), and every wrong guess costs points.

Play the built-in hits catalog, or connect Spotify and play your Liked Songs, playlists, saved albums, top tracks, recently played, followed artists or top artists. Anyone can also paste a public Spotify or Deezer playlist, album or artist link without logging in.

Everything is configurable: number of rounds, snippet lengths, where the snippet starts (beginning, middle, random), release year range, genres, artists to include or exclude, explicit songs, live/remix versions, songs per artist, scoring curve, wrong-guess penalty, and whether suggestions come from your pool or any song. Finished games produce a challenge link so friends can play the exact same songs.

## How audio works

- **30s previews (default, works for everyone).** Each song is matched to a preview from Spotify, Deezer or iTunes and played with the Web Audio API, so a 0.1s snippet is exactly 0.1s. Previews are excerpts chosen by the music service, so "beginning" means the start of the excerpt (silence and fade-in are skipped).
- **Full tracks (Spotify Premium, beta).** Uses the Spotify Web Playback SDK to play the real track, so snippets can start at the true beginning of the song. Needs Premium and a desktop browser. Timing is approximate because Spotify controls playback.

## Architecture

Next.js app with no database. The only server code is two small API routes that run as Vercel serverless functions:

- `/api/deezer/*` proxies Deezer's public catalog API (it has no CORS headers).
- `/api/spotify-embed` reads Spotify's public embed pages, which is how links work without a login.

Spotify login uses Authorization Code with PKCE entirely in the browser, so there is no client secret and no session storage on a server. The hits catalog (`public/catalog.json`) is generated by `npm run build:catalog`.

## Setup

```bash
npm install
cp .env.example .env.local   # add your Spotify client ID
npm run dev                  # open http://127.0.0.1:3000 (Spotify rejects "localhost")
```

### Spotify app

1. Create an app at https://developer.spotify.com/dashboard and tick **Web API** and **Web Playback SDK**.
2. Add redirect URIs: `http://127.0.0.1:3000/callback` for local dev and `https://<your-domain>/callback` for production.
3. Put the Client ID in `NEXT_PUBLIC_SPOTIFY_CLIENT_ID`.
4. Under **User Management**, add the Spotify account emails that should be able to log in. Development-mode apps allow 5 users and the app owner needs Premium. Spotify only grants extended quota to large organizations, so for everyone else the "Paste a link" tab (no login) is the way in. Players can also enter their own client ID under "Use your own Spotify app".

Development-mode apps can only read the contents of playlists the user owns or collaborates on. For other playlists Earshot falls back to the public embed page, which returns the first 100 songs.

## Deploying to Vercel

Import the repository in Vercel, set **Root Directory** to `earshot`, add `NEXT_PUBLIC_SPOTIFY_CLIENT_ID`, and deploy. No other server is needed. Remember to add the production `/callback` URL to the Spotify app.
